# DECISIONS.md — Choix techniques HESYD ONE

| # | Choix | Raison | Alternative écartée |
|---|---|---|---|
| D1 | Prisma + SQLite (fichier `db/custom.db`) | Environnement sandbox sans PostgreSQL ; SQLite réel avec contraintes d'unicité et transactions. Schéma porté tel quel vers PostgreSQL/pgvector (types réservés `embeddingJson`) | MongoDB écarté (relations + intégrité requises) |
| D2 | Recherche : lexical réel (SQLite LIKE scoring + mots-clés extraits par GLM stockés en `searchTerms`) | Pas d'endpoint embeddings dans le SDK ; index mots-clés généré par le vrai modèle = couche sémantique légère honnête, aucun faux « vectoriel » | pgvector réservé à la migration PostgreSQL ; jamais simulé |
| D3 | Auth maison : scrypt (node:crypto) + sessions en base (SHA256 du jeton), cookie httpOnly | Zéro dépendance, multi-organisation + rôles simples à contrôler à la main à chaque requête | NextAuth v4 écarté (couche d'abstraction inutile ici, complexité callbacks) |
| D4 | Agent = boucle d'actions JSON structurées (GLM) + outils réels, streaming SSE | Le SDK n'expose pas de function-calling natif ; JSON strict validé par zod = même garant, contrôle total des outils | Vercel AI SDK écarté (couche inutile pour 7 outils) |
| D5 | ~~OCR réel via `zai.chat.completions.createVision`~~ **REMPLACÉE par directive mission (contrôle architectural final)** : OCR via **Google Document AI uniquement** (`connectors/document-ai.ts`, contrat REST `processors:process`) ; aucun moteur alternatif — sans configuration, erreur explicite `docai_non_configure`, fichier A_VERIFIER, réception ERREUR_DEFINITIVE reprise possible | Google Document AI imposé par la mission ; tout repli OCR alternatif supprimé (le repli VLM historique a été retiré du code) | Tesseract.js ET tout moteur VLM/ML en repli OCR écartés (substitution interdite) |
| D6 | PDF via pdfkit (WinAnsi couvre le français), XLSX via exceljs, DOCX via `docx` | Génération réelle côté serveur, fichiers ouvrables, zéro service externe | Puppeteer écarté (trop lourd pour des rapports) |
| D7 | Archivage : connecteur `local` actif (fs réel, mêmes règles confirmation/cachet) + connecteur Drive OAuth REST réel dormant | Le produit doit fonctionner réellement maintenant ; Drive s'active avec `GOOGLE_*` env sans changer une ligne de logique métier | Simuler Drive écarté par principe |
| D8 | WhatsApp : connecteur Cloud API réel (HMAC X-Hub-Signature-256, téléchargement média Graph API) dormant sans env | Code de production exact ; webhook rejette tout événement non signé plutôt que d'en accepter un faux | WAHA écarté (POC isolé seulement, hors périmètre actuel) |
| D9 | Scheduler in-process (scan 60 s, verrous `lockedAt/lockedBy`, clé d'idempotence par créneau) | Pas de Docker/n8n dans la sandbox ; les règles s'exécutent réellement (rapports, rappels) | n8n obligatoire en production : contrat signé fourni, export workflows prévu, dormant |
| D10 | ~~Stripe REST~~ **REMPLACÉE par directive mission** : **Polar** seul fournisseur de paiement/abonnement (`connectors/polar.ts` : Checkout hébergé + webhooks signés Standard Webhooks idempotents, route `/api/webhook/polar`) ; le connecteur Stripe et sa route webhook ont été supprimés du code | Polar imposé par la mission ; l'état d'abonnement n'est modifié QUE par des webhooks Polar vérifiés | Stripe et tout autre prestataire de paiement écartés (architecture parallèle interdite) |
| D11 | Voix réelle : MediaRecorder navigateur → base64 → `zai.audio.asr.create` → transcription traitée comme instruction | ASR réel disponible ; message vocal = instruction réelle | Whisper local écarté (latence/déploiement) |
| D12 | i18n : clés extraites du code réel puis dictionnaires FR/EN complets | Aucun texte en dur ; EN livré complet ou pas du tout | next-intl écarté (routage inutile : une seule page) |
| D13 | Une seule page `/` : landing publique + application authentifiée en vues clientes (zustand) | Contrainte plateforme (une route visible) ; sections = navigation client-side | Pages multiples écartées par la plateforme |
| D14 | Fonts auto-hébergées via @fontsource (Fraunces variable, Instrument Sans variable) | next/font/google dépend du réseau à chaque build ; fontsource est versionné dans le dépôt | Google Fonts CDN écarté (RGPD + réseau) |
| D15 | Rattachement client dérivé du groupe (source de vérité unique) — un envoi de formulaire n'envoie que le groupe, le client est résolu serveur | Le groupe appartient déjà à un client ; impossible d'avoir un couple client/groupe incohérent | Double saisie client+groupe avec validation croisée écartée (duplications de vérité) |
| D16 | Fichier bloqué avant archivage = « reprise » et non « doublon » : même sha256 retrouvé non-ARCHIVE → rattachement révisé, artefacts dérivés recalculés, journal conservé | La déduplication ne doit jamais enfermer un document dans un état d'erreur ; le document lui-même et son journal restent intacts | Re-créer un nouveau record écarté (doubles de documents interdits) |
| D17 | Boucle agent tolérante au protocole : forme canonique {"action":"outil"…} ET forme raccourcie {"action":"rechercher_documents",…} normalisées serveur | GLM émet naturellement les deux formes ; la tolérance supprime les boucles silencieuses sans affaiblir les gardes-fous (recherche préalable exigée, anti-répétition) | Prompt strict seul écarté (fragile en production réel) |
| D18 | Déclenchement manuel des automatisations (« Exécuter maintenant ») via le même contrat que le créneau planifié, slotKey distinct | Vérification réelle de la règle par l'utilisateur sans attendre le cron ; même code d'exécution = mêmes preuves | Endpoint séparé « dry-run » écarté (deux chemins = divergences) |
| D19 | Deux espaces explicites — « Documents » (tous rôles) et « Console opérateur » (PROPRIÉTAIRE/ADMINISTRATEUR) via commutateur de segments en tête de barre latérale | L'app de production sépare l'usage quotidien de la gestion ; le même `view` unique pilote les deux espaces (store) | Deux routes distinctes écartées (contrainte une-route + perte d'état) |
| D20 | Console opérateur en 5 registres à onglets avec chargement paresseux réel par onglet (équipe, intégrations, abonnement, journaux d'audit, paramètres) | Chaque registre charge sa donnée à l'ouverture ; le journal d'audit expose les vraies lignes horodatées (jointure manuelle User) | Tout charger à l'ouverture écarté (lents et inutile) |
| D21 | Marque vectorielle inline `HesydMark` (SVG, `currentColor` → `var(--cachet)`) + variantes statiques (`/logo.svg`, `app/icon.svg`) dans le cachet exact #C13B20 (oklch(0.545 0.175 33)) | Thémable clair/sombre sans double fichier, monogramme gravé sans dépendance de police | PNG généré par IA écarté (flou, non thémable, non vectoriel) |
| D22 | Gestion d'équipe réelle : changement de rôle, désactivation (révocation immédiate des sessions), retrait d'accès, révocation d'invitation — jamais sur le PROPRIÉTAIRE ni soi-même, chaque action auditée | La console doit gérer l'accès comme un vrai SaaS ; la pérennité de l'organisation est protégée par des gardes-fous serveur | Suppression physique de comptes écartée (documents conservés, traçabilité) |
